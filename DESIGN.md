# Construction Companion design

The owner-approved construction world is retained. This is an Operate surface: the active question and real task state lead; the canvas supplies a small, lively setting.

Tokens: paper #F5F0E6; ink #24211D; orange #C35A21; muted ink #635B50; surface #FFFDF7; boundary #D8CDBD; success #356447. Body uses a readable system sans; modest serif headings echo a project notebook. Type scale 14/16/20/28/36 px. Spacing 4/8/12/16/24/32/48 px. Controls have at least 44 px hit areas, visible focus, and labels.

The first viewport places the pixel construction site beside the engineer's readable question. Below it, a compact crew roster and activity list provide evidence. A connection form precedes project data. Workers selected for roles stand ready; only observed activity drives construction. No fictional completion percentage.

Motion: local sprite walking/tool movement only when connected and observed activity exists. Pause when hidden, paused, offline or reduced motion is requested. Canvas is decorative; HTML carries every state and action.

User flow: connect → choose session → answer or select skill → return to native host for permissions. Installation, stale replies, disconnected service and memory conflicts each have explicit states.
