# Local foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish measured host capabilities and a durable, authenticated local companion core.

**Architecture:** Start with harmless native-host probes, then build a small SQLite event/state store and loopback HTTP service. No host settings are changed by tests unless they use an explicitly isolated fixture home.

**Tech Stack:** Node.js >=22.13.0, ESM/JSDoc, node:sqlite, node:http, node:test; initial verification on 22.16.0.

**Spec:** `../specs/2026-11-07-construction-companion-v2-design.md`; shared types: `2026-11-07-construction-companion-contracts.md`.

## Global Constraints

- The existing coding host owns execution. The companion creates no model session or model API request.
- V2 lives in its own construction-companion repository. V1 source, services, history and public prototype tags are preserved.
- Event payload limit is 16 KiB encoded UTF-8. HTTP request limit is 64 KiB. Return at most 100 events and at most 768 KiB per replay page. The local metadata spool is capped at 5 MiB; overflow produces an explicit history-gap marker.
- Memory capture starts disabled. Default memory is a dedicated private project folder; selecting an existing vault requires an explicit path choice.
- User-ready compatibility requires native-host evidence on every advertised host/version/platform. Fixture tests alone do not qualify a host. Unsupported or unverified capabilities are labelled explicitly.

## Review Focus

- A missing Claude executable must produce an unverified capability, not a passing native probe — Task 1.
- Equal event IDs with different bodies must conflict while genuine retries deduplicate — Task 2.
- A restart during state mutation must not partially accept a question or lose an acknowledged event — Task 2.
- An unrelated website must not be able to mutate the loopback service through browser requests — Task 3.
- Oversized or secret-bearing hook data must be rejected before storage — Tasks 2 and 3.

### Task 2: Validated events and transactional state

**Files:** Create `src/contracts.mjs`, `src/core/store.mjs`, `test/store.test.mjs`; modify `test/helpers.mjs` to export `openTemporaryStore(t)`.

**Interfaces:** Consumes `Scope`, `Event`, `StoredEvent`. Produces `validateEvent(input): Event` and `openStore(databasePath): Store`. `Store` exposes synchronous `append(event): {cursor, duplicate}`, `list(scope, {after=0, limit=100}): StoredEvent[]`, `read(scope, key): {version:number,value:unknown}|null`, `compareAndSet(scope,key,expectedVersion:number|null,value): {version,value}`, `transaction(fn): unknown`, and `close(): void`. `compareAndSet` rejects mismatched versions. Nested domain operations use one synchronous transaction.

- [ ] Write `test/store.test.mjs` with assertions: appending the same canonical event twice leaves one row and returns the same cursor; changing its payload rejects with `CONFLICT`; scope A never reads scope B; out-of-order source sequences remain replayable in durable cursor order; invalid schema, nested transcript payloads and a 16,385-byte payload reject before insertion; 101 requested events return at most 100 and obey the 768 KiB page budget; rollback preserves the prior state version; close/reopen preserves acknowledged events and state. Use real temporary SQLite files for persistence tests.
```js
test('event retries deduplicate and conflicting bodies reject', t => {
  const store = openTemporaryStore(t);
  const e = event({eventId:'same'});
  assert.equal(store.append(e).cursor, store.append(e).cursor);
  assert.equal(store.list(scope, {}).length, 1);
  assert.throws(() => store.append({...e,payload:{label:'changed'}}), {code:'CONFLICT'});
});
```

- [ ] Run `node --test test/store.test.mjs`. Expect module/export failure before implementation.
- [ ] Implement the contract validators and `openStore` using SQLite WAL, migrations and parameterized statements. Use `events` with scope/eventId uniqueness and `state` with scope/key uniqueness plus compare-and-set versions. Append/read operations are bounded; unknown payload keys are rejected by type-specific allowlists. A `history.gap` records dropped metadata without guessing events. Store no tokens, raw prompts or reasoning. Reject transactions crossing asynchronous callbacks.
- [ ] Run `node --test test/store.test.mjs`. Expect all assertions to pass, including restart and rollback cases.
- [ ] Stage the task files and commit with `git commit -m "feat: persist validated scoped events and versioned state"`.

### Task 3: Authenticated loopback service and browser session handles

**Files:** Create `src/core/service.mjs`, `src/server.mjs`, `src/private-paths.mjs`, `test/server.test.mjs`.

**Interfaces:** Consumes `Store`, `Scope`. Produces `createService({store, now, memoryRoot}): Service`, initially exposing `registerSession(scope): string`, `ingest(event): {cursor,duplicate}`, `sessions(): {sessionKey,host,status}[]`, `events(sessionKey,after): StoredEvent[]`, `close(): void`. Later tasks add domain methods. Produces `startServer({service, tokens, port=0}): Promise<{origin,close}>`, and `resolvePrivatePaths({platform,env,projectRoot}): {dataRoot,memoryRoot}`. Tokens are injected, never returned by browser endpoints.

- [ ] Write `test/server.test.mjs`: a real request with the wrong token gets 401; a mutation with an external Origin or mismatched Host is rejected; the UI token cannot call `/ingest`; the ingest token cannot read `/api/sessions`; a 65,537-byte body gets 413 before parsing; unknown session handles get 404; closing the server releases its port. Assert public responses omit private paths and token values. Assert default private paths avoid the repository and OneDrive on Windows.
```js
test('wrong token cannot inspect sessions', async t => {
  const service = createService({store:openTemporaryStore(t),now:()=>0,memoryRoot:temporaryDirectory(t)});
  const server = await startServer({service,tokens:{ingest:'i'.repeat(64),ui:'u'.repeat(64)}});
  t.after(() => server.close());
  const r = await fetch(server.origin+'/api/sessions',{headers:{authorization:'Bearer wrong'}});
  assert.equal(r.status,401);
});
```

- [ ] Run `node --test test/server.test.mjs`. Expect missing exports/routes.
- [ ] Implement the service and server. Bind only `127.0.0.1`; use separate random 32-byte bearer tokens, constant-time comparison, strict Host/Origin checks and no permissive CORS. Browser connection uses a password-style token field held in memory, not URL/localStorage. Serve static files with a restrictive CSP and no remote scripts. Routes: ingest-token-only `POST /ingest`; UI-token-only `GET /api/sessions`, `GET /api/events?sessionKey=&after=`. Generate opaque session handles mapped to registered scopes. Resolve private storage from the OS user-data location; reject a default located under source/OneDrive. A user-selected vault is separate from service credentials. Do not auto-open a browser with credentials in its URL.
- [ ] Run `node --test test/server.test.mjs test/store.test.mjs test/compat.test.mjs`. Expect all passing; verify the bound address is loopback.
- [ ] Stage the task files and commit with `git commit -m "feat: serve authenticated local companion sessions"`.
