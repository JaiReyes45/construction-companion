# Native acceptance gates

A release must record the exact host version, platform, package SHA256, tested date, native/fixture distinction and outcome. Never put credentials or user transcripts into public evidence.

- Clean install and removal preserve an unrelated plugin, config edits and notes. Verify native hook trust, package paths with spaces and reload behavior.
- An ordinary website prompt reaches genuine installed Superpowers. Its question appears in the game and the one answer returns to that exact native request.
- Duplicate, replaced, timed-out, disconnected and interrupted questions cannot resume the wrong task. Test 45-second fallback; separately measure any claimed long wait.
- Recommend an installed architect skill, accept it, choose another, and decline. A decline suppresses a repeated offer for that role/task.
- Use a harmless pinned fixture skill to exercise explicit installation review, native permission, failed install, verification and required reload. Download success alone is insufficient.
- Opt into project memory, resume selected context, create an editor conflict, reconcile it and opt out. Unrelated vault pages remain untouched.
- Stop/restart the daemon, replay events and reconnect. Failed tasks never complete construction. Multiple sessions remain isolated.
- Verify keyboard use, 320px layout, 200% zoom, reduced motion, offline controls and native permission return. Record external network requests and exposed host usage; otherwise label usage unknown.

Current receipts establish automated local behavior and isolated Codex package registration only. Full ordinary-prompt acceptance and native Claude/Linux runs remain open. `scripts/release-check.mjs` rejects ready claims without matching native receipts; a clean preview source scan does not promote these capabilities.
